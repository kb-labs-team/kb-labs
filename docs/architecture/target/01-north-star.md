# 01 — North star и принципы (DRAFT v0)

> Черновик по обсуждению. `?` = гипотеза, нужна правка владельца.

## Для кого

- **Сейчас:** автор и узкий круг — dogfooding, ежедневное использование на десятках рабочих проектов.
- **Потом:** выход на весь рынок после узких кругов и тестов. Поэтому контракты версионируем с самого начала, но LTS, air-gapped и enterprise-поставку сейчас **не строим**.
- **Два режима, один продукт:** локальный (одиночка) и облачный (команды, деплой автора). Одна кодовая база, две топологии.

## Обещание опыта

Скачал приложение → оно само поставило платформу и провело за руку → открылся Studio → добавил проекты
и включил нужные плагины/адаптеры → переключаешься между проектами без командной строки.
Командная строка остаётся для автоматизации и агентов, а не для повседневной работы.

## Принципы

1. **Платформа одна на машину**, проект в неё регистрируется (как проекты в Claude Code / Codex).
2. **Проект — параметр, а не набор сервисов.** Число процессов не растёт с числом проектов.
3. **Цельность важнее распределённости локально.** Локально — один хост-процесс с модулями; сервисы отдельными процессами — только там, где нужна изоляция или масштаб (воркеры плагинов, облако). ?
4. **Граница платформы жёсткая.** Плагин видит платформу только через версионируемый SDK-контракт; второй копии платформы в рантайме быть не может.
5. **Декларация отдельно от состояния.** То, что проект *хочет* (конфиг, плагины и версии), — в репозитории. То, что *происходит* (логи, кэши, pid, порты) — вне репозитория.
6. **Человек, агент и CI идут в один движок** (ADR-0028): UI — оболочка над теми же операциями.
7. **Архитектура записана и проверяется:** схемы живут в репозитории, инварианты — линтами (см. `docs/ARCHITECTURE-BOUNDARIES.md`).

## Non-goals (пока)

- Enterprise-поставка: LTS-ветки, air-gapped, лицензионные ключи.
- Самообслуживаемый marketplace сторонних вендоров с монетизацией.
- Микросервисная топология как режим по умолчанию для локального запуска.

## Приоритет

Главное — выполнить весь план миграции (`07-migration.md`) в обозримом будущем; порядок внутри не критичен, если сохраняются зависимости этапов.

## Отложено (nice to have, не блокирует)

- **Подпись кода и нотаризация установщика** (Windows SmartScreen, macOS Gatekeeper), каналы обновления stable/canary, публичное место загрузки. Сейчас цель — лаунчер в состоянии «сел и поехал» для узкого круга; до широкого выхода не трогаем.
- Политика совместимости SDK для внешних авторов; телеметрия и согласие; хранение секретов в системном хранилище; корпоративные прокси/зеркала; бюджеты ресурсов (RAM, холодный старт).

## Критерий успеха (предложение)

Время от установки до первой пользы ≤5 минут; число дней подряд без ручного вмешательства в ежедневном использовании автором; число проектов, реально используемых через платформу. ?
