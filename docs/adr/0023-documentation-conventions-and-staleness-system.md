# ADR-0023: Documentation Conventions & Staleness Prevention System

**Date:** 2026-05-29
**Status:** Accepted
**Deciders:** KB Labs Team
**Last Reviewed:** 2026-05-29
**Tags:** documentation, dx, ci, automation, conventions

## Context

The KB Labs docs site accumulated ~112 MDX pages with no enforced structure. Over time
this created several problems:

- **URL chaos** — inconsistent naming (`product-sdk` vs `sdk`, mixed kebab/camelCase)
- **Structural drift** — some directories missing `index.mdx` or `_meta.json`
- **Staleness** — no mechanism to detect when code changes made docs inaccurate
- **Edit-on-GitHub 404** — index pages (resolved from `dir/index.mdx`) generated
  edit links pointing to `dir.mdx` which doesn't exist
- **No ownership** — no mapping between code paths and doc pages; anyone could
  change `services/workflow/core/executor.ts` without knowing which docs to update

At 90+ pages and growing, manual discipline doesn't scale. A constraint-based system
is needed.

## Decision

### 1. Single source of truth: `CONVENTIONS.md`

All rules live in `sites/web/apps/docs/CONVENTIONS.md`:
- URL structure: max 2 levels, always kebab-case, no trailing slash
- File naming: section roots are always `index.mdx`, pages are `[slug].mdx`
- Frontmatter schema: `title` required, 5 allowed fields total
- Component naming: `Docs[Name].tsx` + `[Name].module.css`, named exports only
- Section registry: locked slugs — rename only with redirect in place

### 2. Machine-readable sitemap: `sitemap.config.json`

Every doc page is declared with:
```json
{
  "slug": "sdk/plugin-api/commands",
  "type": "manual | hybrid | auto",
  "owners": ["sdk/sdk/src/command/**"],
  "stalenessRisk": "high | medium | low"
}
```

`owners` are glob patterns pointing to code paths that, when changed, should trigger
a doc review. `type: "auto"` pages are generated by CI and never edited by hand.
`static: true` marks pages with no code dependency (privacy, runbooks) — suppresses
owners warning.

### 3. Structural audit: `docs-audit.mjs`

Eight checks run via `kb-devkit check` (registered as `docs-audit` custom check):

| # | Check | Severity |
|---|-------|----------|
| 1 | Every sitemap slug has a matching MDX file | error |
| 2 | Every MDX file is listed in the sitemap | warning |
| 3 | Every MDX has required `title` frontmatter | error |
| 4 | All filenames/directories are kebab-case | error |
| 5 | Every content directory has `index.mdx` | error |
| 6 | Every content directory has `_meta.json` | warning |
| 7 | Max 2 directory levels inside `content/en/` | error |
| 8 | Non-auto, non-static pages have at least one owner | warning |
| 9 | i18n parity: activates when `content/{locale}/` appears | warning/error |

Check 9 is dormant until a second locale directory is created. When `content/ru/`
appears, it automatically starts flagging missing translations and orphaned
translated pages.

### 4. PR staleness bot: `.github/workflows/docs-bot.yml`

On every PR:
1. Computes changed files (`git diff BASE...HEAD`)
2. Matches them against `owners` globs in `sitemap.config.json`
3. Posts a summary comment with affected doc pages grouped by staleness risk
4. Posts up to 5 inline review threads on the changed code files
5. Posts `REQUEST_CHANGES` review if structural audit has errors

Matching uses specificity scoring: if `sdk/sdk/src/command/**` (depth 4) matches,
patterns at depth < 3 are filtered out. This prevents broad globs like `sdk/**`
from flooding the PR when a deep-path file changes.

Branch protection on `main` enforces:
- "Require a pull request before merging"
- "Require conversation resolution before merging"
- "Require status checks to pass" → `docs-bot` job

### 5. SDK section merge

`product-sdk/` (for product builders) merged into `sdk/platform-client/`.
`sdk/` flat pages moved into `sdk/plugin-api/`.
Rationale: two audiences, one section with subsections — avoids confusing
`/sdk` vs `/product-sdk` split.

### 6. Edit-on-GitHub fix

`DocsLayout.tsx` now receives `isIndex: boolean` from `getDocPage()`.
Edit URL is constructed as `slug/index.mdx` when `isIndex=true`, preventing 404
on GitHub for section root pages.

## Consequences

### Positive

- Merge is blocked if audit has errors — no workarounds, constraint-based
- PR bot surfaces affected doc pages without manual tracking
- Single config file (`sitemap.config.json`) drives both the audit and the bot
- i18n parity check is future-proof — zero cost until Russian content starts
- `static: true` flag cleanly distinguishes "no owner by design" from "forgot to add owner"

### Negative

- Every new doc page must be registered in `sitemap.config.json` — extra step
- `owners` globs need to be kept in sync with codebase refactors
  (e.g. renaming `services/workflow/` would silently break staleness detection)
- Inline PR threads require manual resolution — can feel noisy on large refactors
  that touch many code paths

### Alternatives Considered

- **Manual discipline** — doesn't scale past ~30 pages with one person
- **Docusaurus / Fumadocs** — heavier migration, deferred; current Next.js MDX
  stack works; conventions are framework-agnostic
- **TypeDoc auto-generation for all pages** — only viable for API reference;
  conceptual docs require human authorship

## Implementation

Files created or modified:

| File | Purpose |
|------|---------|
| `sites/web/apps/docs/CONVENTIONS.md` | Canonical conventions doc |
| `sites/web/apps/docs/sitemap.config.json` | Sitemap + owners registry |
| `sites/web/apps/docs/scripts/docs-audit.mjs` | Structural audit (8 checks) |
| `sites/web/apps/docs/scripts/docs-staleness.mjs` | Changed-files → affected pages |
| `.github/workflows/docs-bot.yml` | PR bot workflow |
| `sites/web/apps/docs/lib/content.ts` | Added `isIndex` to `getDocPage()` return |
| `sites/web/apps/docs/components/DocsLayout.tsx` | Fixed edit-on-GitHub URL |
| `devkit.yaml` | Registered `docs-audit` custom check |

**Maintenance rules:**
- Adding a doc page → add entry to `sitemap.config.json`
- Adding a code module → add to `owners` of the relevant doc pages
- Renaming a doc section → add redirect, update slug in sitemap
- Starting a new locale → create `content/{locale}/` — audit activates automatically
