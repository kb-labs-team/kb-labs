## Goal

A fresh platform install has useful local persistent adapters without asking
the user to choose providers, add adapter bindings, or install an external
adapter service. Every selected default is replaceable with
`kb adapter bind <slot> <package>`; changing providers does not migrate or
delete data already stored by the previous provider.

Implicit default adapter state uses `<KB_HOME>/state/<projectId>/`. When a
project has not been registered yet, `projectId` is derived from its canonical
absolute path per ADR-0044; later registration of that path uses the same ID.
Relative paths from platform adapter configuration resolve beneath the single
platform data root: `<workspace>/.kb/data` in development and
`<install-root>/state/data` when installed. Absolute configured paths remain
absolute.

## Prerequisites

- [ ] A clean platform root and one initialized project.
- [ ] The platform package registry is available for the install itself.

## Steps

| # | Action | Expected |
|---|---|---|
| S-054.1 | Install the platform in local mode and in secured mode using the default install flow without selecting adapters or adding adapter config, then run `kb adapter list --json` from each registered project | Both installs resolve the same built-in providers for every platform slot with a persistent local implementation: `storage` is `@kb-labs/adapters-fs` with base directory `<KB_HOME>/state/<projectId>/storage`; `documentDatabase` is `@kb-labs/adapters-sqlite`; `kvStore` is `@kb-labs/adapters-sqlite/kv`; `analytics` is `@kb-labs/adapters-analytics-sqlite`; `eventBus` is `@kb-labs/adapters-eventbus-cache` backed by the local StateBroker; `logger` is Pino; and `logs` is `HybridLogReader` backed by the logger ring buffer and SQLite persistence. Persistent defaults resolve beneath `<KB_HOME>/state/<projectId>/` and leave the repository untouched. These rows report their resolved provider and never fall back to `inmemory`. Every local implicit provider can be constructed with the declared default options and needs no external network service. `serviceTransport` is not an implicit default because it requires a services map. `cache` uses the local StateBroker; `invoke`, `artifacts`, `config`, and `notifier` use in-process implementations. `llm` defaults to `@kb-labs/adapters-openai`; with no key, its row reports `credentialsStatus: "missing"` and `missingCredentials: ["OPENAI_API_KEY"]`. `embeddings` defaults to `@kb-labs/adapters-openai/embeddings` and reports its missing OpenAI credential without blocking installation or startup. `vectorStore` defaults to `@kb-labs/adapters-sqlite/vector-store`. `snapshotManager` remains unconfigured. |
| S-054.2 | Immediately after a clean platform install, with the installed host running and no optional provider or external adapter service configured, run `kb-create doctor --platform-root "$PLATFORM_ROOT" --json`, then run `kb-create doctor --platform-root "$PLATFORM_ROOT"` | Both forms exit 0 even when the sealed platform package set includes launcher binaries without package manifests. `installed`, `running`, `reachable`, `platform.ok`, and overall `ok` are `true`. JSON includes warning-severity `KB_ADAPTER_CREDENTIALS_MISSING` findings for `llm` and `embeddings`, names `OPENAI_API_KEY` without printing its value, and reports actions to set the key for each capability. The text form shows `Installed: yes`, `Running: yes`, and `Reachable: yes`, plus a `Warnings` section with both actions. Both forms list every slot returned by `GET /health/adapters` with its `slot`, `mode`, and `implementation`, including real adapter records that omit the optional `reason` field. `storage` is `real` with implementation `@kb-labs/adapters-fs`; the `logs` slot is `real` with implementation `HybridLogReader`. Starting the host with the implicit OpenAI adapters and no key succeeds, with every runtime peer imported by the installed SDK available in the sealed platform package set. Configured adapter load failures and their slot-level diagnostics are specified by [S-211.6](S-211-optional-adapter-failure-visibility.md#steps). |
| S-054.3 | From a registered project with no project adapter settings and no active project runtime, run the documented `e2e-hello` workflow and inspect its completed record and host health | The first workflow request starts that project's lazy runtime; the run succeeds and `<KB_HOME>/state/<projectId>/storage/workflows/<runId>.json` exists with the same `runId` and terminal `success` status. Host health lists the project runtime as `ready`, required machine-level upstreams remain ready, the project inherits the installed platform storage default, and the repository gains no KB Labs runtime state. |
| S-054.4 | Inspect `kb adapter list --json` for each defaulted plugin-visible slot and run `kb-create doctor --platform-root "$PLATFORM_ROOT" --json` | Local default providers report `networkRequired: false`; OpenAI LLM and embeddings report `networkRequired: true` and their credential state separately. Doctor reports local defaults healthy and missing OpenAI credentials for optional capabilities as warning-severity findings; it remains `ok: true` and exits 0 unless an error-severity finding is present. |
| S-054.5 | With `OPENAI_API_KEY` unset and no explicit LLM binding, stage a small tracked-file change and run `kb commit plan create --json` | The Commit plugin's default enables LLM generation, so the command uses the implicit OpenAI provider and returns one JSON result envelope with `ok: false` and `error.code: KB_ADAPTER_CREDENTIALS_MISSING`, naming `OPENAI_API_KEY` and the supported configuration command `kb config set --scope platform platform.adapterOptions.llm.apiKey '${OPENAI_API_KEY}' --allow-missing-env`. It exits cleanly without a stack trace, secret value, or fabricated commit plan. |
| S-054.6 | Install `@kb-labs/mind` with `kb marketplace install @kb-labs/mind --scope platform --json`, seed one vector in the `default` namespace through `POST /platform/v1/vectorStore/upsert`, then run `kb mind search --text "adapter defaults" --json` with `OPENAI_API_KEY` unset | Platform-scope plugin installation leaves the registered project repository unchanged. Search reaches the implicit SQLite vector store and then returns a typed `KB_ADAPTER_CREDENTIALS_MISSING` error for `embeddings`; it does not report `KB_ADAPTER_NOT_CONFIGURED` for `vectorStore`, print a stack trace (including a Go panic/goroutine dump or Node/Python traceback), or return an empty-success search result. |
| S-054.7 | Stop the installed host, then run `kb-create doctor --platform-root "$PLATFORM_ROOT" --json` and its text form | Both forms exit 0 and report that adapter status cannot be checked because the host is stopped. JSON is an ADR-0049 success envelope with `data.operation: "doctor"`, `data.status: "unhealthy"`, and the adapter check; both forms give the exact next command `kb-create start --platform-root "$PLATFORM_ROOT"` and neither prints a raw connection error. |
| S-054.8 | Leave `OPENAI_API_KEY` and `platform.adapterOptions.llm.apiKey` unset on a fresh platform with the implicit OpenAI default; inspect `kb adapter list --json` and `kb-create doctor --platform-root "$PLATFORM_ROOT" --json`, then run `kb commit plan create --json` | Adapter list reports `credentialsStatus: "missing"`; doctor reports `KB_ADAPTER_CREDENTIALS_MISSING` as a warning with action `set OPENAI_API_KEY to enable LLM features`, exits 0, and remains `ok: true`. Neither prints a credential value. The command returns typed `KB_ADAPTER_CREDENTIALS_MISSING` naming `OPENAI_API_KEY` and the exact supported configuration command `kb config set --scope platform platform.adapterOptions.llm.apiKey '${OPENAI_API_KEY}' --allow-missing-env`; its hint says no request was sent. The OpenAI adapter constructs successfully without the key and fails only when a request is attempted. |
| S-054.9 | In a fresh local install, complete a workflow run, write one document and one KV value through the platform's installed service APIs, run `kb-create restart --platform-root "$PLATFORM_ROOT"`, then read each item again | The completed workflow run, document, and KV value remain available with their original IDs and contents. `kb adapter list --json` and `kb-create doctor --platform-root "$PLATFORM_ROOT" --json` show the configured persistent built-in providers for `documentDatabase`, `kvStore`, `storage`, `analytics`, and the log slots in local mode. |
| S-054.10 | On a fresh install with a real SQLite analytics event already in the allocated database, remove `analytics` from `platform.adapters` and `platform.adapterOptions` in `$PLATFORM_ROOT/.kb/kb.config.jsonc`, restart the host, then run `kb adapter list --json` from the registered project and `kb-create doctor --platform-root "$PLATFORM_ROOT" --json` | The host restart succeeds and the installed platform resolves `@kb-labs/adapters-analytics-sqlite` from its local default adapter manifest; the slot is real and healthy without a user-added binding. The same valid SQLite database remains readable and retains the event after restart. Doctor remains `ok: true` and exit 0, with a warning for the missing optional OpenAI credential when `OPENAI_API_KEY` is unset. Analytics persists at `<KB_HOME>/state/<projectId>/analytics/analytics.sqlite`; no analytics state is written into the repository. |
| S-054.11 | Record the platform receipt and installed package versions, write an analytics event to the default SQLite database, run `kb marketplace install @kb-labs/adapters-analytics-file --scope platform`, then run `kb adapter bind analytics @kb-labs/adapters-analytics-file` and inspect the selected adapter and original database path | The selected provider is the requested package. Marketplace resolves it to an exact immutable version and catalog integrity and records both together in the platform lock. That version-plus-integrity pair is the package identity; the platform receipt and every installed package version under platform `node_modules` are identical before and after the adapter install and bind. The original SQLite database remains on disk and is not migrated or deleted; the replacement starts with only the data it owns. |
| S-054.12 | With the sealed installed platform config and adapter lock in place, run `kb adapter list --json` from a registered project while another platform owns the default Gateway port | The command exits successfully, reports this installed platform's defaults from its receipt-backed Gateway address, and does not report another platform's adapter state or print an adapter-constructor exception or stack trace. |
| S-054.13 | On an installed platform, remove one package's `kb-create.manifest.json` projection, run `kb-create doctor --platform-root "$PLATFORM_ROOT" --json`, then run `kb-create doctor --platform-root "$PLATFORM_ROOT" --fix --json` | Plain doctor exits 0 with the ADR-0049 success envelope: `data.operation: "doctor"`, `data.status: "unhealthy"`, and a typed manifest-projection finding that names the affected package and gives `kb-create doctor --fix`; it does not create or modify any manifest. `--fix` exits 0 with a success envelope and recreates the projection only after verifying the installed package name and version against the receipt. |
| S-054.14 | On an installed platform, remove one sealed artifact's `overrides` entry from `pnpm-workspace.yaml`, then run `kb marketplace install @kb-labs/adapters-analytics-file --scope platform --json` | The command exits non-zero and stdout contains one JSON object with `ok: false` and an `error` envelope whose code is `KB_MARKETPLACE_PLATFORM_ARTIFACT_PINS_MISSING`, message is `The installed platform is missing kb-create's sealed artifact overrides. No package was installed.`, correlation ID is present, and hint gives `kb-create update --platform-root <platform-root>` followed by the exact marketplace install to retry. The platform receipt, package versions, package manifest and pnpm config remain unchanged. Pin validation derives the full sealed artifact set from the installed receipt and does not pass when that set is empty. |
| S-054.15 | Run a fresh default `kb-create install` with `OPENAI_API_KEY` unset and no adapter options, then inspect the resolved plan and installed platform | Installation succeeds without prompting for `openai.apiKey`; the plan retains its optional warning metadata and action `set OPENAI_API_KEY to enable LLM features`, so doctor and `kb adapter list` can report the missing credential. |
| S-054.16 | After a fresh platform install, start a fresh Node process and import every runtime export of the installed SDK and each bundled plugin | Every runtime export resolves from the installed platform tree without `ERR_MODULE_NOT_FOUND`; any failure names the missing module and the importing package. SDK exports declared non-runtime by its package manifest are excluded from this import check, and SDK test/build helper packages are absent from the installed platform. |
| S-054.17 | In a fresh, unregistered repository with no `.kb/` directory, run `kb --help` and `kb --version` | Both commands exit successfully and leave the repository tree unchanged; neither creates `.kb/`. Global help and version are platform-scoped global flags, so startup does not initialize project-scoped adapters or write adapter state into the repository. |
| S-054.18 | On an installed platform whose built-in adapter manifests provide defaults and which has no user-written `.kb/kb.config.json[c]`, run `kb adapter list --json` from a registered project | The command succeeds and reports the same installed default providers as S-054.1. A missing optional user config is a valid default state on installed platforms as well as solo development checkouts; absent `platform.mode` does not make the config invalid. |
| S-054.19 | Run a workflow that requires host gateway dispatch when its runtime has no `KB_GATEWAY_URL` | The command returns the typed `KB_HOST_SERVICE_ADDRESS_MISSING` error, names the missing `gateway` address, preserves its correlation ID, and tells the operator to start the host with `kb-create start`. |
| S-054.21 | From a registered project's directory in an installed platform, run a system command that initializes platform-configured SQLite and analytics adapters, then run a plugin command | Both commands leave the repository tree byte-for-byte unchanged. The configured database and analytics files are under `<install-root>/state/data`. The project still uses `<KB_HOME>/state/<projectId>/` for implicit default adapters. |
| S-054.22 | Set `platform.adapterOptions.documentDatabase.filename` to `.kb/database/kb.sqlite`, then to `../outside.sqlite`, and start a command that initializes that adapter | Each startup fails with catalogued `KB_CONFIG_INVALID`, identifies the offending `platform.adapterOptions.documentDatabase.filename` field, and explains that relative paths cannot begin with `.kb/` or escape the data root. The first hint gives `kb config set --scope platform platform.adapterOptions.documentDatabase.filename 'database/kb.sqlite'`; the second gives `kb config set --scope platform platform.adapterOptions.documentDatabase.filename 'outside.sqlite'`. No file is created at either invalid location. |
| S-054.23 | Remove the active version's `.kb/v2/platform-layout.json` while leaving a contract only at `<install-root>/.kb/v2/platform-layout.json`, then run `kb adapter list --json` | The command exits 1 with `KB_CONFIG_INVALID`; `error.details.contractPath` is `<install-root>/current/.kb/v2/platform-layout.json`, `error.details.remedyOperation` is `update`, and `error.details.remedyPlatformRoot` is the install root. The catalog-owned hint gives the kb-create repair next step. It refuses to use the stable-root contract or its `.kb/data` projection. |

| S-054.24 | On a fresh default install with `OPENAI_API_KEY` unset and no adapter config, run `kb adapter list --json`, install `@kb-labs/mind`, seed one vector in the `default` namespace through `POST /platform/v1/vectorStore/upsert`, then run `kb mind search --text "adapter defaults" --json` | Adapter listing resolves `embeddings` to `@kb-labs/adapters-openai/embeddings` and reports `credentialsStatus: "missing"` with `missingCredentials: ["OPENAI_API_KEY"]`. Installation and host startup succeed without the key. With a vector present, the first embeddings request returns an error envelope with `code: KB_ADAPTER_CREDENTIALS_MISSING`, identifies `OPENAI_API_KEY`, and gives the exact command `kb config set --scope platform platform.adapterOptions.embeddings.apiKey '${OPENAI_API_KEY}' --allow-missing-env`; no OpenAI request is sent and no stack trace or secret value is printed. |
| S-054.25 | On a fresh default install, write a vector record with a stable ID, vector and metadata through the installed platform API, restart the host with `kb-create restart --platform-root "$PLATFORM_ROOT"`, then search for the same vector | `vectorStore` resolves to `@kb-labs/adapters-sqlite/vector-store` without user adapter configuration. After restart, search returns the original ID and metadata with the cosine similarity score. Its SQLite file is `<KB_HOME>/state/<projectId>/vector-store/vectors.sqlite`; the project repository remains unchanged. |

## Dependencies

- Workflow run-record persistence through the configured `IStorage` adapter is
  owned by the workflow stream. S-054.3 depends on that feature.
- S-054.5 and S-054.6 require the commit and Mind command plugins respectively;
  their expected missing-capability errors are owned by the adapter/runtime
  error path.
- `snapshotManager` remains optional and unconfigured because the existing
  local filesystem provider implements a different runtime contract.
