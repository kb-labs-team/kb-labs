Create a working plugin with two CLI commands using the scaffold tool, then customize it.

## Prerequisites

- A running KB Labs workspace (`kb --help` works).
- Node.js <NodePolicy />.x and pnpm installed.

## 1. Scaffold the plugin

```bash
kb scaffold run plugin my-plugin --yes
```

This generates a ready-to-build plugin at `.kb/plugins/my-plugin` as one package named `@kb-labs/my-plugin`:

| Path | Purpose |
|------|---------|
| `package.json` | Package name matches the plugin manifest ID |
| `src/manifest.ts` | Manifest and CLI command registry |
| `src/cli/commands/` | CLI command handlers |
| `src/core/` | Business logic, kept separate from platform adapters |
| `src/contracts/` | Types and schemas shared inside the package |

Two commands come out of the box: `hello` (greeting with a `--who` flag) and `ping` (health check).

The scaffold creates the source files. Build them, then link the package into the project's marketplace lock.

Use `--dry-run` to preview the file tree without writing anything:

```bash
kb scaffold run plugin my-plugin --dry-run --yes
```

### Options

| Flag | What it does |
|------|-------------|
| `--scope @acme` | Use a custom npm scope (default: `@kb-labs`) |
| `--out ./path` | Write to a custom directory instead of `.kb/plugins/<name>` |
| `--force` | Overwrite if the target directory already exists |

## 2. Install dependencies and build

```bash
cd .kb/plugins/my-plugin
pnpm install
pnpm build
```

The build writes the package output to `dist/`. If the build fails, run `kb scaffold doctor --path .kb/plugins` to diagnose.

## 3. Link and run the plugin

Return to the project root and link the built package. The relative path is recorded in `.kb/marketplace.lock`:

```bash
cd ../../..
kb marketplace plugins add --link .kb/plugins/my-plugin
```

Now run the generated commands:

```bash
kb my-plugin hello
# Hello, World from my-plugin!

kb my-plugin hello --who=Alice
# Hello, Alice from my-plugin!

kb my-plugin hello --json
# { "greeting": "Hello, World from my-plugin!" }

kb my-plugin ping
# pong @ 2026-04-15T12:00:00.000Z
```

Check the help:

```bash
kb my-plugin --help
```

## What got generated

### Manifest (`src/manifest.ts`)

The manifest declares the plugin's identity, permissions, and CLI commands. Each command points at a handler file:

```
handler: "./cli/commands/hello.js#default"
```

The path is relative to the package root, pointing at the built `.js` output (not `.ts` source). The `#default` suffix tells the runtime to use the default export.

### Command handler (`src/cli/commands/hello.ts`)

Handlers use `defineCommand` from `@kb-labs/sdk`. They receive a `PluginContextV3` (platform services) and `CLIInput<Flags>` (parsed flags):

```ts
export default defineCommand({
  id: 'my-plugin:hello',
  description: 'Say hello from my-plugin',
  handler: {
    async execute(ctx: PluginContextV3, input: CLIInput<HelloFlags>) {
      const { greeting } = hello({ who: input.flags.who ?? 'World' });
      ctx.ui?.info?.(greeting);
      return { exitCode: 0, result: { greeting } };
    },
  },
});
```

Notice the handler calls into `src/core` for logic, not platform internals. This keeps business logic testable without platform mocking.

### Core logic (`src/core/hello.ts`)

Pure functions, zero platform imports. The generated file includes commented cookbook examples for LLM calls, caching, and structured logging via `@kb-labs/sdk`.

### Tests (`src/core/tests/hello.test.ts`)

Unit tests run with vitest, no platform setup needed:

```bash
cd .kb/plugins/my-plugin
pnpm test
```

## 4. Add a new command

Three steps:

**a)** Create `src/cli/commands/status.ts`:

```ts
import { defineCommand, type CLIInput, type PluginContextV3 } from '@kb-labs/sdk';

export default defineCommand({
  id: 'my-plugin:status',
  description: 'Show plugin status',
  handler: {
    async execute(ctx: PluginContextV3, input: CLIInput<{ json?: boolean }>) {
      const payload = { version: '0.1.0', healthy: true };
      if (input.flags.json) {
        ctx.ui?.json?.(payload);
      } else {
        ctx.ui?.info?.(`my-plugin v${payload.version} — healthy`);
      }
      return { exitCode: 0, result: payload };
    },
  },
});
```

**b)** Add the command to `manifest.ts` in the `cli.commands[]` array:

```ts
{
  id: 'status',
  group: 'my-plugin',
  describe: 'Show plugin status',
  handler: './cli/commands/status.js#default',
  handlerPath: './cli/commands/status.js',
  flags: [
    { name: 'json', type: 'boolean', description: 'Emit JSON' },
  ],
  examples: ['kb my-plugin status'],
}
```

**c)** Add the entry to `tsup.config.ts`:

```ts
entry: {
  index: 'src/index.ts',
  'cli/commands/hello': 'src/cli/commands/hello.ts',
  'cli/commands/ping': 'src/cli/commands/ping.ts',
  'cli/commands/status': 'src/cli/commands/status.ts',  // new
},
```

Then rebuild:

```bash
pnpm build
kb my-plugin status
```

## 5. Add LLM support

The cookbook in `src/core/hello.ts` has commented examples. To enable LLM access:

**a)** Update permissions in `manifest.ts`:

```ts
const permissions = combinePermissions()
  .with(kbPlatformPreset)
  .withPlatform({ llm: true })
  .build();
```

**b)** Use `useLLM` in your handler:

```ts
import { useLLM } from '@kb-labs/sdk';

const llm = await useLLM(ctx);
const res = await llm.complete({
  prompt: `Write a greeting for ${name}.`,
  maxTokens: 40,
});
```

This requires an LLM adapter configured in `kb.config.json`. See [Adapters → Overview](/adapters).

## Iterating

- **Code change?** `pnpm build` — cache updates automatically, then re-run.
- **Something broken?** `kb scaffold doctor --path .kb/plugins` scans for common issues.
- **Want to remove it?** `kb marketplace plugins remove @kb-labs/my-plugin`.
