The marketplace manages extension packages for the installed KB Labs platform. Plugin installs made from a project leave its package manifest, package-manager lockfile, and `node_modules` alone. The project records its selected plugin's exact version, tarball integrity, source kind, and enabled state in schema v3 of `.kb/marketplace.lock`. A project pin stores no absolute or machine-specific path and no installation timestamp; the runtime resolves the version through that machine's shared store.

## Install and manage a project plugin

Run these commands from the project root:

```bash
kb marketplace install @kb-labs/commit@1.2.3
kb marketplace plugins list
kb marketplace plugins disable @kb-labs/commit
kb marketplace plugins enable @kb-labs/commit
kb marketplace uninstall @kb-labs/commit
```

Replace the example package and version with the published plugin you need. Commit `.kb/marketplace.lock` to share the project pin. The package itself is kept in the machine's shared extension store. If a project pin points to a missing store entry, reinstall it with `kb marketplace install <package[@version]>`. When an older v2 lock is rejected, regenerate it with `kb marketplace sync`.

A local plugin can be linked explicitly after building it:

```bash
pnpm build
kb marketplace plugins add --link .kb/plugins/my-plugin
```

Build the generated workspace before linking the plugin package. The path is relative to the project root, and the link is recorded in `.kb/marketplace.lock`.

To create that workspace from an existing project, run `kb scaffold run plugin my-plugin`, then follow its printed build and link steps. The first command is available after the link succeeds.

## Install and bind an adapter

Adapters are installed and bound at platform scope. Every project uses the same configured provider:

```bash
kb marketplace install @kb-labs/adapters-fs@1.2.3 --scope platform
kb adapter bind storage @kb-labs/adapters-fs
```

`kb adapter bind` writes `platform.adapters.storage` in platform config. It refuses packages that are absent from the platform lock or are not adapters. Use `kb config set --scope platform platform.adapterOptions.storage '{"baseDir":"storage"}'` to configure adapter options at platform scope. A project config with `platform.adapters` or `platform.adapterOptions` fails with `KB_ADAPTER_PROJECT_SCOPE`; move those fields to platform config.

Studio's project Plugins page accepts a package spec and installs or uninstalls through host routes; its enable switch updates the project lock. Adapter settings are not project settings.

## Lock ownership

`.kb/marketplace.lock` is read by shared discovery. Project plugin installs and enable/disable actions update the project lock; uninstall removes the project pin. Platform adapter installs update the platform lock and platform package graph. Binding an adapter changes platform config. Installing a project plugin does not modify `package.json`, the package-manager lockfile, or `node_modules`.

## HTTP API

The marketplace module exposes package management below `/api/v1/marketplace` on the host gateway. Package actions use request bodies, for example `POST /api/v1/marketplace/packages/install` with `{"specs":["@kb-labs/example@1.2.3"],"scope":"project"}`.

Local platforms bind the gateway to loopback and do not require login. Secured platforms require an authenticated session. In secured mode, sign in with `kb auth login` before running a marketplace mutation.
