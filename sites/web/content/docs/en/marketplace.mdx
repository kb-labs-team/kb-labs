## Install a plugin in a project

From a KB Labs project, install a plugin at an exact version:

```bash
kb marketplace install @kb-labs/commit@1.2.3
```

The project records an exact version, tarball integrity, source kind, and enabled state in schema v3 of `.kb/marketplace.lock`. The package lives in the machine's shared extension store; the lock contains no machine path or install timestamp. The install does not change your `package.json`, package-manager lockfile, or `node_modules`. Commit the marketplace lock with your project. If a v2 lock is reported, run `kb marketplace sync` to regenerate it.

## Develop a local plugin

From a KB Labs project, scaffold and build a plugin, then link its entry package with a project-relative path:

```bash
kb scaffold run plugin my-plugin
cd .kb/plugins/my-plugin
pnpm install
pnpm -w build
cd ../../..
kb marketplace plugins add --link .kb/plugins/my-plugin
kb my-plugin hello
```

The link command records the local package in `.kb/marketplace.lock`; generated files are not registered automatically.

Use `kb marketplace plugins disable <package>` and `kb marketplace plugins enable <package>` to change the project pin's enabled state. `kb marketplace uninstall <package>` removes the pin.

## Install and bind an adapter

Install the adapter in the platform package graph, then bind it to a platform slot:

```bash
kb marketplace install @kb-labs/adapters-fs@1.2.3 --scope platform
kb adapter bind storage @kb-labs/adapters-fs
```

The bind command writes `platform.adapters.storage` to platform config. Adapter options are platform scoped and can be set with `kb config set --scope platform platform.adapterOptions.storage '{"baseDir":"storage"}'`. Projects inherit these settings. In Studio, use the selected project's **Plugins** page to install, enable, disable, or uninstall plugins.

The bind fails if the package is not listed as an adapter in the platform marketplace lock. Install it first with the exact `kb marketplace install … --scope platform` command shown above.
